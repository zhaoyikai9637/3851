HTTP 测试的数据层使用 `tests/helpers/memory-repository.cjs`，生产启动只会使用 MySQL Repository。普通测试不保证 MySQL 服务器配置或 SQL 执行已经验证。

## 在你的电脑补充数据库联调

配置好 `.env`、启动 MySQL 后执行：

```powershell
npm run test:integration
```

该测试使用真实 MySQL 连接，创建独立临时测试库，检查表结构、数据读取与恢复、事务失败不部分保存、并发排期、请求去重、SQL 参数化与邮件附件落库。邮件发送仍然使用测试 transport，不会对外发送。测试完成后仅清理它新建的临时测试库。

## 手动验收建议

1. 初始化并导入演示数据，登录后查看四个初始阶段的数量。
2. 选 Alex Tan，转 Interview，并选择准备邮件；确认申请、操作记录、HR 内部通知、草稿均更新。
3. 安排将来的面试，给另一人使用相同面试官或房间安排重叠时间，确认被阻止；首尾相接可以安排。
4. 改期，检查之前的 schedule 草稿已失效；拒绝该候选人，检查预约被取消且内部备注没进入邮件。
5. 从 Interview Results 选择候选人，填写 Offer，以普通 HR 登录尝试审批应失败；经理批准后记录接受。
6. 新建候选人及申请，上传实际 PDF；刷新并重新登录，确认记录与 PDF 仍可读取。
7. 用两个浏览器会话查看同一工作区，一方保存后另一方使用旧数据保存，应提示先刷新。
8. 创建/编辑/预览/归档模板；修改资料；检查不同 HR 账号的已读状态互不影响。
9. 配置自己的 SMTP 并用自己的收件邮箱测试，确认成功消息进入 Notification Log；不配置 SMTP 时不出现虚假的成功记录。

对于真实 MySQL/SMTP 环境出现的错误，保留终端错误代码和网页 requestId，可以定位到对应接口；不要把密码贴进错误截图。
