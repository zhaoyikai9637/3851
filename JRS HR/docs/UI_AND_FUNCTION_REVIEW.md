# 界面与功能核对

版本 2.2.0 · 2026-10-05

## 页面变化

- 电脑端固定左侧导航与页头；申请、职位、面试、通知、邮件及模板采用分页。
- 列表行数随窗口高度调整，保留全部数据、筛选与导出。
- 简历默认适合整页，可手动放大、翻页；岗位要求与技能职责分栏切换。
- 拒绝、进入面试按钮固定在审核区底部。
- 创建职位、收取申请、编辑候选人使用紧凑双列表单；长表单只滚动内容，保存按钮保持可见。
- 报表切换概览、职位表现、待办任务；候选人资料和历史分开查看。
- 手机使用可展开菜单与申请卡片，允许必要纵向滚动，不强行裁切内容。

## 修复的问题

1. 首页写死 Sarah：改为当前登录用户姓名。
2. 最近申请的排序和翻页顺序不准确：先按创建时间从新到旧排序，校正页码，再分页。
3. 上传真实 PDF 后打印入口可能生成示例简历：真实简历统一打开已上传 PDF；无简历时阻止示例打印。
4. 从职位切换申请列表时筛选可能被路由重置：改为在路由完成时应用职位筛选。
5. 通知中的 View Application 一律打开简历审核：现在根据申请当前阶段进入正确详情。
6. 拒绝记录的通知状态只判断是否曾有任何邮件：区分未准备、草稿、发送中、待核实及已发送。
7. 通知和邮件按 UTC 截断日期：改成按页面显示的 Asia/Singapore 日期筛选。
8. 上传简历遇到版本冲突后持续失败：加载最新数据后可重试相同文件。
9. 发信尚未配置时仍可点击列表 Send：显示明确状态并禁用直接发送，草稿功能继续可用。
10. 排期选择中重复出现已有预约的申请：排除已安排面试的申请。

|---|---|
| HR 登录、经理/员工权限、资料编辑、退出 | 已验证；员工不能批准 Offer 或管理模板 |
| 新申请、已有候选人申请、候选人资料、PDF 上传与下载 | 已验证，数据保存到 MySQL |
| 待审核→面试，拒绝及原因确认 | 已验证 |
| 排期、改期、取消、反馈、时间冲突检查 | 已验证；会议结束前不能录入最终反馈 |
| 反馈→Offer、批准、草稿、录用接受 | 已验证 |
| 任务、模板、通知已读、邮件记录、导出 | 自动与页面检查覆盖；SMTP 使用测试替身验证，不代表真实邮箱已配置 |
| Offer / Rejected 五年自动清理 | 单元与真实 MySQL 测试通过；依赖服务运行；不自动清理历史导出文件或备份 |
| 小组统一后台与数据库 | 尚未对接，仍需统一后端源码和字段约定 |
| 真实邮件投递 | 尚未配置；“邮件服务器接受”不等于“对方收件箱已收到” |
