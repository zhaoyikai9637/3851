# Reliability fixes - 2026-11-03

Application status loads its application and profile independently. A failed application request renders an explicit retry state; only a successful empty response means no current application. A slow or unavailable profile cannot hide a stored application. Visibility changes wait for the profile to load.

MySQL connections use TCP keepalive, bounded idle retention and validation before a transaction lease. Autonomous, side-effect-free SELECT statements may retry once after a recognized connection interruption. Locked reads, writes and write transactions are never replayed. Sequelize uses the same boundary and does not silently retry writes. This improves recovery without claiming to eliminate network outages.

HR email sending retains one persistent draft ID. If the send response is lost, the client checks an authenticated, read-only status endpoint. It never automatically resends. Sent results refresh the full workspace revision; Sending offers a status check; Uncertain requires provider reconciliation. Duplicate in-flight client sends share one operation. This does not establish delivery to a real inbox.

Recruitment synchronization writes changed business records instead of rewriting all jobs and applications for every command. Publication-only edits explicitly identify their target job, preserving dates and metadata synchronization. Canonical templates use one parameterized bulk upsert. Applicant identity synchronization first checks an existing row instead of opening a create transaction on every read; profile sections load concurrently. Permissions and revocation are still checked per request.

Validation: 185 integrated tests (184 suite tests plus the separately verified authenticated-status test), 136 React tests, 183 communication server/API tests and 125 native HR tests pass; production builds pass. Isolated Aiven and Edge regression verifies the genuine Accepted application, injected profile/application failures and retry, one captured email after deliberately losing a successful send response, immutable sent history, and read recovery after disconnecting only the test script's own connection. No production business writes or real emails are used. In this QA run message-draft saving took about 12 seconds and sending with response-loss reconciliation about 22 seconds; these are observations, not a guarantee for all operations or the public deployment.
